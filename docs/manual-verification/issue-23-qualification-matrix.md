# Issue #23 qualification matrix

This matrix is the release record for [issue #23](https://github.com/abdullahnettoor/ohmytheme/issues/23). Run it against a locally signed build on macOS 14 or later. Use [`clean-machine-fresh-account.md`](clean-machine-fresh-account.md) for the end-to-end run and the linked target checklists for detail.

## Status rules

- `Pending` means no dated repository evidence proves the live check.
- `Partial` means dated evidence proves only the part named in the Evidence column. The remaining procedure is still pending.
- `Pass` requires a dated record with the app version, macOS version, target version, observed report, and any support limit.
- `Fail` means the observed behavior differs from the expected result, user-owned state changed outside the approved boundary, a report overstates Activation Reach, or a required action is unavailable.

Do not record configuration contents, account names, home-directory paths, VS Code profile identifiers, socket nonces, process identifiers, wallpaper URLs, or other real user values. Record versions, counts, redacted target labels, outcome text, and hashes only.

## Fail or narrow-support rule

1. Mark the run `Fail` immediately if Oh My Theme loses user-owned state, changes an unselected Target, overwrites an external edit, exposes private configuration, uses a private or unsafe workaround, reports a stronger Activation Reach than observed, or lacks live Undo or Restore and Disconnect for a supported connected Target.
2. Narrow support only when the failed capability is independently optional, the report states the limitation exactly, safe Target results remain intact, and this table can name a smaller edition, version, profile, configuration shape, display scope, or capability promise that passed.
3. Never turn a failure into support by adding GUI automation, private preferences, direct application-database writes, undocumented process termination, or force overwrite.
4. Keep a check `Pending` until a dated live record exists. A unit test, source inspection, or disposable proof can justify `Partial`, not a live `Pass`.
5. Issue #23 can close only when every required row is `Pass` or has an explicit narrow-support decision, and no blocking rule above applies.

## Deferred work

Developer ID, notarization, packaging, updates, telemetry, pricing, and external beta are deferred. They are not qualification steps for the locally signed vertical demo and must not be presented as completed by this matrix.
